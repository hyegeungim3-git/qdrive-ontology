# Qdrive 온톨로지 — 데이터 체계 · 흐름 · 활용

1. **데이터 체계가 어떻게 이루어져 있나** — 무엇을 어떤 자리에 놓고, 어떻게 잇는가

# 1부. 데이터 체계가 어떻게 이루어져 있나

## 1-1. 문제부터

버스 한 대가 하루에 만들어 내는 기록은 많습니다. 속도, 엔진 회전수, 위치, 급감속, 연료, 민원.
이걸 표에 쌓아 두면 **숫자는 보이는데 뜻이 안 보입니다.**

> 안전점수가 72점입니다.
> — 왜 72인가요?
> — …계산식이 그렇습니다.

이 대화가 안 되면 그 점수로는 아무것도 못 합니다. 기사에게 설명할 수도, 예산을 붙일 수도 없습니다.
**「왜」에 답하려면 숫자끼리 어떻게 이어져 있는지를 미리 정해 둬야 합니다.** 그게 온톨로지입니다.

## 1-2. 9개 자리 (스페이스)

모든 데이터는 아래 아홉 자리 중 하나에 놓입니다. 자리를 아홉 개로 **제한한 것**이 핵심입니다.

| 자리 | 무엇이 놓이나 | 예 |
|---|---|---|
| **규정** | 무엇을 허용하고 금지하는가 | 접근 권한, 보존 기간, 가명 처리, 불이익 결정 금지, 유효 구간 |
| **자산** | 다루는 대상 | 차량, 노선, 정류장, 차내 단말 |
| **주체** | 사람과 조직 | 기사, 관제 담당, 담당 공무원 |
| **관측** | 실제로 기록된 사실 | 운행 회차, 위험운전 패킷, 센서 측정, 위치, 기사 소명 |
| **개념** | 분류 기준 | 위험운전 유형, 노선 등급, 연료 종류 |
| **판정** | 관측에 대한 판단 | 정당 판정, 민원 사실 판정, 노선 준수, 고장 예측, 몰림 판정 |
| **집단** | 묶어야 보이는 것 | 운전군, 노선군 |
| **성과** | 바뀐 숫자 | 안전점수, 경제운전, 연료 절감, CO₂ 감축, 정시율, 배차 간격 |
| **조치** | 되돌리는 행동 | 실시간 코칭, 배차 권고, 예지정비, 안전 인센티브, 전기 전환 |

아홉 자리 안에 **노드 타입 38종**이 있습니다. 노드 타입이란 「이 자리에 놓이는 것의 종류」입니다.
예를 들어 관측 자리에는 운행 회차·위험운전 패킷·센서 측정·위치 관측·기사 소명 다섯 종이 있습니다.

## 1-3. 핵심은 네 자리를 잇는 한 줄

아홉 자리 중 **네 자리가 뼈대**입니다.

```
관측  ──뒷받침한다──▶  판정  ──반영된다──▶  성과  ◀──올린다──  조치
(사실)                 (판단)              (숫자)            (행동)
```

이 한 줄이 이 도구가 있는 이유입니다. 다시 아까 질문으로 돌아가면:

> **안전점수 72점은 왜 72인가요?**
>
> 3742호의 72점은 급진로변경 3건·급가속 7건의 감점 판정이 반영된 값이며,
> 그중 1건은 방어운전으로 인정돼 복원됐습니다. 근거가 된 기록은 00:35:12에 남았습니다.

이 문장은 사람이 쓴 게 아니라 **그래프를 거꾸로 걸어가서 조립한 것**입니다.
성과에서 판정으로, 판정에서 관측으로 되짚어 올라갑니다.

## 1-4. 연결에도 규칙이 있다

아무 자리끼리나 이을 수 없습니다. **11개 방향에만, 정해진 30가지 표현으로만** 이을 수 있습니다.

| 출발 → 도착 | 쓸 수 있는 말 |
|---|---|
| 주체 → 자산 | 운전한다, 관리한다, 조회권한, 승인권한 |
| 자산 → 관측 | 생성한다, 기록된다 |
| 관측 → 개념 | 분류된다, 예시가 된다 |
| **관측 → 판정** | **뒷받침한다**, 반박한다, 시각을 고정한다 |
| **판정 → 성과** | **반영된다**, 보정한다 |
| 개념 → 성과 | 기여한다, 제약한다, 예측한다, 악화시킨다 |
| **조치 → 성과** | **올린다**, 낮춘다, 안정시킨다, 최적화한다 |
| 조치 → 개념 | 바꾼다 |
| 집단 → 개념 | 묶는다, 요약한다 |
| 규정 → 자산 | 보호한다, 등급을 매긴다, 제한한다 |
| 규정 → 주체 | 허용한다, 금지한다, 승인을 요구한다 |

**얼마나 제한적인가:**

| | 개수 |
|---|---|
| 이론상 만들 수 있는 조합 | 9 × 8 × 30 = **2,160** |
| 실제로 허용된 조합 | **30** |
| 허용률 | **1.4%** |

> 문법의 값어치는 무엇을 할 수 있는지가 아니라 **무엇을 못 하는지**에 있습니다.
> 연결을 자유롭게 만들 수 있으면 당장은 편하지만, 반년 뒤에는 아무도 그 연결이 무슨 뜻인지 모릅니다.

앱의 **④ 규칙 시험**에서 직접 조합을 눌러 왜 막히는지 확인할 수 있습니다.

## 1-5. 값에도 규칙이 있다

노드 타입마다 어떤 값을 갖는지 정해져 있습니다(**속성 90개**). 예를 들어 위험운전 패킷은:

| 속성 | 자료형 | 단위 | 조건 |
|---|---|---|---|
| eventType | 문자 | — | 공단 표준 8종만 (급가속·급출발·급감속·급정지·급진로변경·급앞지르기·급좌우회전·급유턴) |
| speedKmh | 소수 | km/h | 0 ~ 120 (시내버스 사양) |
| rpm | 정수 | rpm | 0 ~ 3000 |
| occurredAt | 일시 | — | 필수 |

**단위를 값에 붙인 이유**는 AI 때문입니다. `0.54`만 넘기면 모델이 해석하지 못합니다.
`0.54 m³/km`여야 뜻이 생깁니다. 수치 속성 30개 모두에 단위가 붙어 있습니다.

## 1-6. 시간이 있는 연결과 없는 연결

모든 연결에 기간을 붙이지 않았습니다. **이 구분이 중요합니다.**

| | 예 | 왜 |
|---|---|---|
| **시간이 있다** (10종) | 운전한다, 조회권한, 금지한다 | 기사는 교대하고, 권한은 회수되고, 규정에는 시행일이 있다 |
| **시간이 없다** | 뒷받침한다, 반영된다, 분류된다 | 「이 기록이 이 판단을 뒷받침했다」는 나중에 거짓이 되지 않는다. 바뀌는 건 판단이지 연결이 아니다 |

그리고 **시간을 두 종류**로 다룹니다.

- **유효 시간** — 현실에서 언제부터 언제까지 참인가 (배정 구간, 규정 시행일)
- **기록 시간** — 우리가 언제 그것을 알았나 (검증 스탬프, 실행 이력)

둘을 함께 가지면 「그때 그 규정이 이미 있었나」와 「그 판단은 어느 규칙으로 났나」에 모두 답할 수 있습니다.

## 1-7. 국제 표준 위에 서 있다

우리끼리만 아는 구조가 아니라는 증명입니다. 표준 10종에 맞춰 놓았습니다.

| 표준 | 무엇을 맡나 |
|---|---|
| **PROV-O** (W3C) | 「무엇이 무엇에서 나왔나」 — 우리 핵심 사슬이 문자 그대로 PROV의 파생 사슬입니다 |
| **SOSA/SSN** (W3C·OGC) | 센서와 관측 — DTG·OBD 산출물이 곧 관측입니다 |
| **Transmodel/NeTEx · GTFS** | 노선·정류장·운행 |
| **SHACL** (W3C) | 규칙 검사 — 실제로 막는 것은 이것입니다 |
| **DQV** (W3C) | 품질 측정 |
| **SKOS** (W3C) | 어휘 매핑 — 정렬 강도를 이 표기로 씁니다 |
| **ODRL** (W3C) | 이용 정책 — 누가 무엇을 할 수 있나 |
| **OWL-Time · GeoSPARQL** | 시간 구간 · 공간 |
| **공단 DTG 409/521** | 국내 법정 운행기록 표준 |

정렬 강도를 **억지로 「완전 일치」라고 주장하지 않습니다.** 인과 어휘 13종은 「우리 고유」로 표시했습니다.
맞다고 우기는 것보다 어디까지 맞는지 적는 편이 나중에 쓸모 있습니다.

# 2부. 데이터는 어떻게 흘러가나

```
① 들어오는 데이터 ─▶ ② 말 바꾸기 ─▶ ③ 검사대 ─▶ ④ 연결된 데이터 ─▶ ⑥ 활용
   DTG/GTFS/BIS        우리 용어로      규칙 확인      점과 선으로
                                          │
                                          ▼ 안 맞으면
                                     ⑤ 막힌 데이터 ─▶ 규칙 고치기
                                                        └─▶ 검사대에 반영
```

## ① 들어오는 데이터 — 원천 3종

| 원천 | 기관 | 주는 것 | 못 주는 것 |
|---|---|---|---|
| **공단 DTG** | 한국교통안전공단 | 1초마다 속도·RPM·위치·가속도·주행거리. 법정 표준이라 이미 전 차량에 달려 있음 | 정당 판정 — 「정당한가」는 사람이 만드는 판단 |
| **GTFS-Realtime** | 국제 표준 | 실시간 위치·노선·정류장 순번 | 엔진 값이 없어 경제운전·안전점수를 못 만듦 |
| **대구 BIS** | 대구광역시 | 정류소 도착 예정, 남은 정류장 | **실제** 도착 시각이 없음 — 그래서 정시율이 아직 「미측정」 |

## ② 말 바꾸기 — 남의 용어를 우리 용어로

원천마다 같은 것을 다르게 부릅니다. 그걸 맞추는 단계입니다.

**세 가지 일을 합니다.**

**(1) 필드를 옮깁니다** — 그대로 / 환산 / 조합

| 원천 필드 | 처리 | 우리 속성 | 주의 |
|---|---|---|---|
| DTG `차량속도` 47 | 그대로 | speedKmh | 단위가 같음 |
| DTG `차량위치X` 461234 | 환산 | lng | 1/100초 정수 → 십진도 |
| GTFS `position.speed` 13.1 | **환산** | speedKmh | **m/s다.** ×3.6을 빼먹으면 47km/h가 13으로 들어감 |
| DTG `운행일자` + `정보발생일시` | 조합 | occurredAt | YYMMDD + HHMMSS를 합침 |

**(2) 안 받을 것을 정합니다**

- `차대번호` — 차량 식별은 등록번호로 충분. **최소 수집 원칙**
- `occupancy_status`(혼잡도) — 우리 체계에 자리가 없음. 받으려면 개정이 필요 (**개정 후보**로 표시)

> 「이 표준을 지원합니다」는 대개 **무엇을 못 받는지**를 안 적어서 성립합니다.

**(3) 같은 차량인지 판단합니다 (엔티티 해소)**

| 원천 | 뭐라고 부르나 | 어떻게 맞추나 |
|---|---|---|
| DTG | `대구70자3742` | 우리와 표기가 같음. 그대로 조인 |
| GTFS-RT | `DGB-3742` (사업자 내부 키) | `label`에 차량번호가 있으면 그것으로 |
| BIS | `3742` (뒤 4자리) | **단독으로는 동일성을 주장할 수 없음.** 노선·시각과 함께 봐야 함 |

## ③ 검사대 — 규칙에 맞는지 본다

여기가 **서비스가 온톨로지 위에서 도는 지점**입니다. 3초마다 돌면서 두 가지를 합니다.

**(1) 통과 여부를 정합니다.** SHACL이 네 종류를 검사합니다.

| 검사 | 예 |
|---|---|
| 속성 | eventType이 공단 표준 8종에 있나, 속도가 0~120인가 |
| 관계 | 「분류된다」가 반드시 있나, 도착지가 개념 자리가 맞나 |
| 문법 | 정해진 11개 방향 밖의 연결이 있나 |
| 업무 규칙 | 근거 없는 판정은 아닌가, 실명이 섞이지 않았나, 감점을 사람이 확정했나 |

걸린 것은 **하류로 안 내려갑니다.** 지우지는 않고 막힌 데이터로 보냅니다.
차량이나 기사를 통째로 빼지 않고 **그 기록 하나만** 뺍니다 — 연좌하지 않습니다.

**(2) 확정값을 다시 계산합니다.**

안전점수를 단말이 준 값 그대로 쓰지 않고, **개념 자리의 감점 가중치**로 그래프를 걸어 다시 셉니다.

```
차량 ─생성한다→ 위험운전 패킷 ─뒷받침한다→ 판정
                     │
             「정당 인정」이면 감점 안 함
             막힌 것도 감점 안 함
             나머지만 유형별 가중치로 감점 (급유턴 2.6 · 급앞지르기 2.4 · 급감속 2.0 …)
```

단말 점수는 **참고치**, 하류로 나가는 것은 **온톨로지가 만든 값**입니다.

> **정직하게 적어 둔 것:** 데이터가 막히면 점수가 **오릅니다.** 감점 근거가 사라지기 때문입니다.
> 「근거 없는 판정은 만들지 않는다」의 결과이지 봐주는 게 아닙니다. 안 적으면 버그로 읽힙니다.

**규정에 시행일이 있으면 그 규칙은 시행 전까지 아예 만들어지지 않습니다.**
「시행 예정이라 아직 적용 안 됩니다」를 화면에만 적으면 그건 말뿐입니다.

## ④ 연결된 데이터 — 점과 선으로 저장

통과한 것이 그래프가 됩니다. 국제 표준 형식(RDF)이라 다른 도시·다른 회사와 합칠 수 있습니다.

```turtle
qdi:evt-대구70자3742-352 a qd:RiskEvent, qd:Evidence ;
  rdfs:label  "대구70자3742 급감속" ;
  qd:eventType "급감속" ;
  qd:speedKmh  "47.00"^^xsd:decimal ;
  qd:occurredAt "2026-08-15T06:03:12Z"^^xsd:dateTime ;
  qd:classifiedAs qdi:rt-급감속 ;      # 개념으로 분류
  qd:supports     qdi:jv-대구70자3742-352 .  # 판정을 뒷받침
```

식별자를 **(차량번호, 시각)** 으로 만듭니다. 순번(`evt-1`)을 쓰면 데이터가 바뀔 때 같은 번호가
다른 기록을 가리켜 링크가 엉뚱한 곳을 엽니다 — 실제로 겪고 고친 부분입니다.

## ⑤ 막힌 데이터 — 지우지 않고 사람에게 넘긴다

막힌 기록마다 **하류 영향**을 함께 계산해 보여줍니다.

| 막힌 것 | 흔들리는 성과 |
|---|---|
| 운행 회차 | 연료 절감률 |
| 위험운전 패킷·판정 | 해당 차량 안전점수 |
| **기사 실명 노출** | **없음** |

마지막 줄이 오히려 유용합니다. 개인정보 위반은 막아도 지표가 안 흔들린다는 것을
**말이 아니라 경로로** 답합니다. 「막으면 손해」라는 반론이 성립하지 않음을 구조로 보입니다.

처리 방법은 세 가지 — **재처리 / 예외 승인 / 원천 수정 요청**.
예외 승인에는 **사유가 필수**입니다. 감사 때 그 문장이 근거가 됩니다.

**단, 규정에서 온 규칙은 예외 승인 버튼이 아예 비활성화됩니다.**
「불이익 결정 자동화 금지」와 「가명 처리」는 클릭 한 번으로 우회할 수 있으면 규정이 아니라 장식입니다.

## ⑥ 규칙 고치기 — 되먹임

같은 규칙에서 자꾸 막히면 **규칙이 현실과 안 맞는 것**입니다.

```
예외 승인이 반복  →  「규칙 재검토」  (규칙이 현실과 안 맞음)
재처리가 반복     →  「원천 점검」    (규칙은 옳음. 단말·통신 문제)
수정 요청이 반복  →  「커넥터 점검」
```

처리 방식의 **분포가 곧 진단**입니다. 같은 건을 예외 승인에서 재처리로 바꾸면 진단이 뒤집힙니다.

역제안 → 개정안 → 승인 → 발행. 발행하면 **검사 결과가 실제로 달라집니다.**
④의 답이 ❌에서 ✅로 바뀌고, ⑤의 근거 사슬이 늘어나고, 같은 결함이 더는 안 걸립니다.

다만 **발행은 소급하지 않습니다.** 이전에 검증된 기록은 옛 규칙 스탬프를 그대로 답니다.
소급할지는 「지금 규칙으로 재검증」 버튼을 누르는 **결정**이어야 합니다.

# 3부. 서비스까지 어떻게 활용되나

## 3-1. 설명 가능한 성과 — 「왜 그 숫자인가」

성과 지표 6종을 각각 관측까지 되짚습니다. **지표마다 사슬이 다릅니다.**

| 지표 | 근거 유형 | 어떻게 |
|---|---|---|
| 안전점수 | 실측 | 위험운전 패킷 → 정당 판정 → 점수 |
| 경제운전 | 실측 | 관성주행·공회전 실측 |
| 연료 절감률 | 실측 | 코칭 미적용 기준선과 실측의 차이 (유가·날씨 제거) |
| CO₂ 감축 | 환산 | 연료 절감량 × 배출계수 2.68 |
| 배차 간격 | 실측 | 위치 관측 → 몰림 판정 → 간격 |
| **정시율** | **미측정** | **원천이 없으면 숫자를 만들지 않는다** — 그 사실 자체를 사슬로 보여줌 |

**근거가 약하면 신뢰도 상한이 낮습니다.** 실측 95% · 환산 85% · 추정 70% · 의견 50%.
강도를 아무리 올려도 이 상한을 못 넘습니다. 모르는 것을 아는 척하지 않는 장치입니다.

## 3-2. 조치를 실제로 내린다 — 쓰기 경로

읽기만 하면 절반입니다. 코칭·배차·정비를 **실제로 발행**할 수 있고,
그 발행이 **온톨로지를 통과**합니다. 네 겹을 지나야 나갑니다.

| 검사 | 묻는 것 |
|---|---|
| 문법 | 이 조치가 이 성과에 붙는 연결이 규칙에 있나 |
| 규정 | 이 역할이 조치를 낼 수 있나. 불이익 조치에 승인자가 있나 |
| 스키마 | 필수 값이 채워졌나 |
| **근거** | **이 차량에 이 조치를 낼 근거가 그래프에 있나** |

마지막이 요점입니다. **위험운전 기록이 하나도 없는 기사에게 코칭을 내리는 것은
근거 없는 감점과 같은 종류의 잘못입니다.** 그 판단을 ⑤ 근거 사슬과 **같은 함수**가 합니다.

발행된 조치는 엔진이 만든 조치와 **같은 자격으로 그래프에 들어갑니다** —
근거 사슬에 나타나고, 검사를 받고, 데이터 목록에 잡힙니다.

## 3-3. 규정이 화면을 실제로 막는다

역할 4종 × 권한 7종. **금지에는 반드시 이유가 붙습니다.**

| 역할 | 할 수 있는 것 | 못 하는 것과 이유 |
|---|---|---|
| 시 담당자 | 전 차량 범위 | 기사 실명 — 시는 노선·통계 단위로 봅니다 / 조치 발행 — 조치는 운행을 책임지는 쪽이 냅니다 |
| 운수사 관제 | 실명·전 차량·원본 위치·예외 승인·**조치 발행** | 문법 발행 — 데이터 책임자가 승인합니다 |
| 기사 | 실명(본인)·원본 위치 | 전 차량 — 동료 비교는 개인 평가 도구가 됩니다 |
| 데이터 책임자 | 전 차량·예외 승인·문법 발행·원본 반출 | **기사 실명** — 관리 권한이 열람 권한을 주지 않습니다 / 조치 발행 — 관리하는 쪽이 운영까지 하면 견제가 사라집니다 |

**두 겹으로 막습니다.**

```
규정   → 「볼 수 있는 것」    (표시 계층)
SHACL  → 「들어올 수 있는 것」 (적재 계층)
```

실명이 원천에서 잘못 들어오면 SHACL이 적재를 막고, 그래도 화면에는 권한 없는 사람에게 안 보입니다.
한 겹만 있으면 어느 쪽이든 뚫립니다.

## 3-4. AI가 받아 쓸 수 있는 데이터로

**데이터 목록(카탈로그)** — 38종 중 34종에 데이터가 있고, 각각 건수·통과율·출처·권한·신선도가 붙습니다.
**손으로 적은 항목이 0개**입니다. 전부 다른 곳에서 파생됩니다.

| 카탈로그 항목 | 어디서 |
|---|---|
| 스키마·자료형·단위 | 검사 규칙과 같은 정의 |
| 상류·하류 | 연결 규칙 + 실제 그래프 |
| 건수·통과율 | 검사대 실행 결과 |
| 신선도 | 실행 이력 |
| 접근 권한 | 규정 자리 |

> 손으로 적는 카탈로그는 반드시 낡습니다. 파생되는 카탈로그만 살아 있습니다.

가장 중요한 칸은 **비어 있는 칸**이라 맨 위에 따로 모읍니다 — 「데이터가 0건인 항목 4개」처럼.
전부 초록불인 목록은 대개 검사를 안 한 목록입니다.

**AI 학습셋 서술(Croissant)** — MLCommons 표준으로 내보냅니다. 값에 세 가지가 붙어서 나갑니다.

1. **의미** — 필드마다 우리 온톨로지 주소를 가리킵니다. AI가 필드 「이름」이 아니라 「뜻」으로 붙습니다
2. **단위** — `0.54`가 아니라 `0.54 m³/km`
3. **한계** — 격리 건수, 통과율, 미측정 지표, 표본 편향을 숨기지 않습니다

## 3-5. RAG · TAG · CAG를 어떻게 쓰나

온톨로지가 있다고 자동으로 되는 게 아니라, **무엇을 어디서 가져올지가 달라집니다.**

| 방식 | 무엇에 | 왜 |
|---|---|---|
| **CAG** (미리 넣기) | 문법 전체 | 26KB라 통째로 컨텍스트에 들어갑니다. 검색할 필요가 없습니다 |
| **TAG** (그래프 질의) | 실데이터 | **LLM이 만든 질의를 ④ 규칙 검증기가 실행 전에 거를 수 있습니다** — 이게 온톨로지의 고유 이점입니다 |
| **RAG** (문서 검색) | 자연어 진입점만 | 「연비가 왜 나빠졌지?」를 어느 지표로 옮길지 |

온톨로지가 환각을 없애 주지는 않습니다. 없애 주는 것은 **「근거를 못 대는 상태」**입니다.

## 3-6. 감사에 제출할 수 있다

- **격리 이력** — 무엇이 왜 막혔고 누가 어떻게 풀었나. 담당자가 적은 사유 원문까지
- **규정 보호 규칙의 우회 여부** — 「불이익 결정 자동화 금지」로 막힌 건수와 우회된 건수.
  정상이면 0건이고 **그 0이 곧 증거**입니다
- **개정 이력** — 어떤 조항이 언제 왜 열렸나. 다음 개정 때 같은 논쟁을 처음부터 하지 않도록
- **실행 이력** — 검사대가 몇 번 돌았나. **「격리 0건」이 깨끗한 건지 검사를 안 한 건지**는 이걸 봐야 갈립니다

# 4부. 데모와 실서비스의 차이

**규모는 다르지만 순서는 같습니다.** 들어올 때 검증하고, 걸리면 격리하고, 통과분만 하류로,
규칙은 발행으로 고칩니다. 순서까지 다르면 그건 데모가 아니라 시연 영상입니다.

| | 이 데모 | 실서비스 |
|---|---|---|
| 그래프 크기 | 스냅샷 1회분 약 150 노드 | 200대 기준 하루 1,700만 패킷 |
| 검사 실행 | 브라우저에서 50~100ms | 적재 파이프라인(pySHACL·Jena) |
| 검사 주기 | 3초 묶음 처리 | 들어오는 즉시 + 하루 한 번 전체 |
| 저장 | 메모리 | 그래프 DB · 원본 5년 |
| 규칙 저장소 | 새로고침하면 초기화 | Git + 자동 배포 |
| 데이터 유입 | 시뮬레이터 | DTG 409/521 · OBD/CAN · RTK · BIS |

**⚠ 규모만 다른 게 아닌 항목 3가지**

1. **접근 통제** — 이 데모는 화면에서 가립니다. 실서비스는 **서버가 애초에 안 내려줘야** 합니다.
   응답에 값이 남아 있으면 뚫립니다. 데모가 증명한 것은 **흐름**이지 구현이 아닙니다.
2. **SHACL의 SPARQL 제약** — 브라우저 엔진이 지원하지 않아 그 규칙만 별도 검사로 돕니다
3. **식별자 발급** — 차량번호를 주소에 직접 넣을지 내부 키로 바꿀지는 발주처와 합의할 사항

## 꼭 눌러 볼 것 세 가지

1. **⑨에서 「표준 밖 코드」를 켜세요** — 규칙이 잡아내고, ⑩에 쌓이고, ⑭의 통과율이 떨어집니다.
   **한 번 누르면 세 화면이 같이 움직입니다.**
2. **맨 위에서 역할을 바꾸세요** — 「기사」는 자기 차량 1대만, 「데이터 책임자」는 기사 이름을 못 봅니다.
3. **⑪에서 새 버전을 내 보세요** — ④의 답이 ❌에서 ✅로 바뀌고 ⑤의 근거가 늘어납니다.

# 부록. 이 도구가 지키는 약속

- **숫자는 모두 실제 계산입니다.** 미리 적어 둔 값이 없습니다. 배속을 올리면 실제로 늘어납니다.
- **모르는 것은 「모른다」고 적습니다.** 정시율은 잴 방법이 없어 값을 만들지 않았습니다.
- **근거가 약하면 신뢰도도 낮습니다.** 실측 95% / 환산 85% / 추정 70% / 의견 50%.
- **불리한 결정은 자동으로 하지 않습니다.** 감점 확정에는 사람의 승인이 필요합니다.
- **빈칸을 먼저 보여 줍니다.** 전부 초록불인 목록은 대개 검사를 안 한 목록입니다.
- **막는 규칙은 우회할 수 없습니다.** 규정에서 온 규칙은 예외 승인 버튼 자체가 비활성화됩니다.
